### Nullable — үсгэн уншилтаас зориудаар татгалзсан, хэмжилт дээр

Даалгавар: *"Nullable зөвхөн канон schema-д nullable гэж зарлагдсан баганад."*
Гэвч **`CANON` нь 60 баганыг БҮГДИЙГ nullable гэж тэмдэглэдэг** — тэр нь Arrow-ийн анхны
утга болохоос "бүгд NULL байж болно" гэсэн үг биш. Үсгээр нь дагавал sorting key ч
Nullable болж, ClickHouse үүнийг зөвхөн `allow_nullable_key` дор зөвшөөрнө.

Тиймээс бодит nullability-г **хэмжив** — 667,809 мөр дээр яг **5 багана** NULL агуулна:

| багана | NULL | % | шалтгаан |
|---|---|---|---|
| `quote_mint` | 167,278 | 25.05 | 2026-05-21-ээс өмнө багана байхгүй |
| `death_age_slot` | 4,938 | 0.74 | censored траектор |
| `death_age_incl` | 28 | 0.00 | censored |
| `death_age_excl` | 17 | 0.00 | censored |
| `accel` | 1 | 0.00 | §3 f2, хуваарь тэг |

Эдгээр 5 нь `Nullable(...)`, үлдсэн **55 нь биш**. Ачаалалтын дараах assert нь багана
тутмын NULL тоог parquet-тэй тулгадаг тул энэ нь **шалгагдсан, таамагласан биш**.

### Timestamp нь String хэвээр

`token_created_at`, `block_time`, `minute_bucket`, `age_min` нь `CANON`-д `large_string`
(Dune-ийн API тэгж буцаасан) тул `String` хэвээр. Launch-цонхны assert нь хадгалалтын
типийг өөрчлөхийн оронд query-ийн үед задлан шинжилнэ.

> **Анхаарах хэрэгтэй:** энэ server нь `Asia/Ulaanbaatar` (UTC+8) timezone-той. Эдгээр
> мөр нь ` UTC` дагавартай тул `parseDateTimeBestEffort(...)`-ыг **timezone заалгүй**
> дуудвал локал цаг руу хөрвүүлж +8 цагаар шилжүүлнэ. Цаашид эдгээр баганыг ашиглах
> бүх query-д `parseDateTimeBestEffort(col, 'UTC')` гэж бичих ёстой (доорх олдвор).

### ОЛДВОР — эхний ажиллуулалт унасан; дата биш, assert буруу байсан

Анхны `verify` дээр `token_created_at ∈ [2026-05-10, 2026-07-03)` нь **6,562 мөр цонхны
гадна** гэж мэдээлж унасан. Хэмжиж оношилсон:

```
server timezone                Asia/Ulaanbaatar (UTC+8)
түүхий мөрийн min / max        '2026-05-10 00:00:12.000 UTC' / '2026-07-02 23:59:39.000 UTC'
parseDateTimeBestEffort(col)   2026-05-10 08:00:12  ..  2026-07-03 07:59:39   (+8ц шилжсэн)
parseDateTimeBestEffort(col,'UTC')  2026-05-10 00:00:12 .. 2026-07-02 23:59:39
цонхны гадна, timezone заалгүй      6,562
цонхны гадна, UTC заасан            0
```

Түүхий мөрүүд нь цонхонд бүрэн багтаж байна — **дата зөв, assert-ийн timezone буруу
байсан**. Хоёр талыг UTC-д бэхэлж зассан; засварын шалтгаан кодод тайлбар болж үлдсэн.
Энэ нь `flow.burst`-ийн timestamp баганыг ашиглах цаашдын бүх query-д хамаарах эрсдэл.

### Хоёр дахь олдвор — DDL-ийн comment дотор цэг таслал

`cmd_schema` нь эхлээд `;`-ээр хувааж, дараа нь тайлбарыг зайлуулж байсан тул DDL-ийн
толгойн `"...can be null; taken literally..."` гэсэн өгүүлбэр SQL-ийг дундуур нь тасалсан
(`SYNTAX_ERROR`). Энэ нь 2026-08-18-нд Dune-ийн query дээр гарсан **яг ижил согогийн
ангилал**. Зассан: **эхлээд** тайлбарын мөрийг зайлуулж, **дараа нь** `;`-ээр хуваана.
