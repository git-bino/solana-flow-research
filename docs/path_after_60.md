Хоёр уншлага тайлагнасан, аль нь ч **загвар биш**:
* **ажиглагдсан** — доош унасан мөрүүд дээрх percentile. Унасан нөхцөлт, бүх токений тухай
  мэдэгдэл болгож үзвэл **доош хазайсан**.
* **доод хязгаар** — censored мөр нь `dur_to_window_end_s`-ээр (үнэний **мэдэгдэж буй доод хязгаар**)
  ордог. Иймд энэ цувааны percentile бүр нь үнэн percentile-ийн **доод хязгаар**.
Kaplan-Meier хийгээгүй, imputation хийгээгүй.

## 2. Тархалт 40 / 50 / 60 хүрэх мөчид

**Ledger нь transfer-aware** — `oh_a`-тай ижил механизм: үлдэгдэл = (авсан − зарсан) + (хүлээн авсан − илгээсэн).
Transfer matview-ийн хамралыг **бичихээс өмнө шалгав**: 2026-05-10 … 2026-08-15 **тасралтгүй**
(xf_02 = 05-10..05-15, xf_03 = 05-16..05-21), токений хамрах хүрээ нь [2026-05-10, 2026-07-03)-ийн
creation бөгөөд бүх cohort-ыг агуулна. Иймд **transfer-гүй ledger рүү шилжих шаардлага гараагүй**.

Transfer matview-д `block_time` **байхгүй**, `block_slot` л бий — тиймээс anchor дээрх таслалт
**slot-оор** хийгдсэн. Slot ба block time хоёр хоёулаа монотон тул энэ нь ижил таслалт.

**Lookahead байхгүй:** шинж бүр `evt_block_time ≤ anchor` арилжаа ба `block_slot ≤ anchor slot`
transfer-ээс л барина. Anchor өөрөө энэ query дотор `virtual_sol_reserves`-ээс гарна, шошгоны
хүснэгтээс уншаагүй.

**Event цонх** [2026-05-10, 2026-05-20] (launch цонх + 1 хоног). `t_anchor_s` p90 = 130 с тул энэ нь
өгөөмөр, гэвч босгыг 05-20-ноос **хойш** анх давсан токен энд **алга**.
