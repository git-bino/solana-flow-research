### OH_conc-ийн `nullif`: OH=0 бүхий burst мөр байдаг

1 өдрийн cohort дээр тоолсон:

| | |
|---|---|
| Burst мөр | 14,300 |
| **OH = 0 (хангасан wallet байхгүй)** | **120 (0.84%)** |
| `oh` aggregate мөр байгаа боловч wallet 0 | 0 |

120 мөр нь `oh` CTE-д **мөр үүсгэдэггүй** (GROUP BY нь хоосон бүлэг гаргахгүй) тул `LEFT JOIN` дараа `oh = NULL → coalesce → 0`, харин `oh_conc = oh_top3 / nullif(0, 0)` = **NULL**. Python лавлагаа тэдгээр мөр дээр `oh_conc = 0` гаргана (`src/oh_reference.py`: `if oh > 0 ... else Decimal(0)`).

Тиймээс **зөрүү нь баталгаажсан, арифметикаар тодорхой: 0.84% мөр дээр SQL NULL, Python 0.** Эдгээр мөр дээр parity-г бодит датаар дахин шалгахад тэдгээр токений түүхий event-ийг татах шаардлагатай (өмнөх parity нь 200 токен = 2.18 MB ≈ 5.5 credit); **ажиллуулаагүй**, учир нь зөрүү нь кодын хоёр мөрөөс гарч байгаа нь ил, мөн бюджет тооллогод зориулагдсан.

## Засвар 1 — траектор slot-индекстэй, тогтмол 75 утга

Хуучин: `array_agg(...) OVER (RANGE 1 FOLLOWING AND 75 FOLLOWING)` нь 75 slot дотрын **event тус бүрийг** цуглуулдаг — индекс нь утгагүй, урт median 28.3, max 788.

Шинэ: индекс `a = 1..75` нь burst-ийн slot-оос хойших **slot зөрүү**, утга нь тэр slot дахь `net_flow_3slot`, event байхгүй slot нь **0**. Хэрэгжүүлэлт:

```sql
slot_nf3 AS (SELECT mint, slot, max_by(nf3_lam, txi * 4096 + ixi) AS nf3_lam_last
             FROM flows GROUP BY mint, slot),
traj AS (SELECT b.mint, b.seq,
                array_agg(coalesce(CAST(s.nf3_lam_last AS double)/1e9, 0.0) ORDER BY off.a) AS nf3_traj_75
         FROM bursts b
         CROSS JOIN UNNEST(sequence(1, 75)) AS off(a)
         LEFT JOIN slot_nf3 s ON s.mint = b.mint AND s.slot = b.slot + off.a
         GROUP BY b.mint, b.seq)
```

`sequence(1,75)`-ийг burst тутам дэлгэж `LEFT JOIN`-оор slot-ын хүснэгттэй холбосон тул урт нь бүтцээрээ 75. **Trino дээр ямар ч оператор унасангүй** — `max_by`, `UNNEST(sequence(...))`, `array_agg(... ORDER BY ...)` бүгд ажилласан. `traj_len` багана нэмж assert болгосон: 14,300 мөр бүр дээр **75**, parity-ийн 88 мөр бүр дээр **75**.

Хоёр конвенц ил бичсэн (spec заагаагүй): нэг slot-д хэд хэдэн event байвал **сүүлийн** (`tx_index, ix_index`-ээр) утгыг авна; event байхгүй slot нь **0** — заасны дагуу, гэхдээ тэр slot дээр trailing 3-slot цонхны *математик* утга нь ерөнхийдөө 0 биш гэдгийг тэмдэглэе.

## Согог

`nf3_traj_75[a]` нь `max_by(nf3_lam, ...)` — тухайн slot дахь **сүүлийн event-ийн trailing утга** — байсан, event байхгүй slot нь 0. Хоёулаа буруу: `nf3(a)` нь `(a−3, a]` мужийн урсгалын **нийлбэр** бөгөөд slot `a` хоосон ч `a−1`, `a−2` дээр арилжаа байсан бол тэг биш.

## Засвар

Slot тутмын **нийлбэр** (`sum(signed_lam)`, `max_by` биш) дээр нягт тор дээр rolling 3-slot нийлбэр:

```sql
slot_flow AS (SELECT mint, slot, sum(signed_lam) AS flow_lam FROM seqd GROUP BY mint, slot)
-- нэг range join биш, ГУРВАН equi-join: (a), (a−1), (a−2)
LEFT JOIN slot_flow f0 ON f0.slot = g.target_slot
LEFT JOIN slot_flow f1 ON f1.slot = g.target_slot - 1
LEFT JOIN slot_flow f2 ON f2.slot = g.target_slot - 2
```

`sf.slot > target − 3 AND sf.slot <= target` гэсэн range join нь 14,300 × 75 торон дээр nested loop болох тул гурван equality join-оор бичсэн — hash join хэвээр. **Trino дээр ямар ч оператор унасангүй.**

Хоёр хувилбар, учир нь §4.3 нь `a = 1, 2` дээр цонх burst slot-оос **өмнөх** slot-уудыг агуулах эсэхийг заагаагүй:

| Багана | Цонх |
|---|---|
| `nf3_traj_75_incl_pre` | `(a−3, a]` нөхцөлгүй — burst slot ба түүнээс өмнөхийг ч агуулна |
| `nf3_traj_75_excl_pre` | зөвхөн `burst_slot`-оос хойших slot-ууд оруулна |

**Аль нь үндсэн болохыг сонгоогүй.** Хоёулаа гаргасан, зөрүү доор тоогоор.

## Засвар 1 — хил нь trigger МӨР, slot биш

`decisions.md`-ийн дагуу: trigger мөрөөс хойших бүх зүйл ирээдүй, үүнд `slot = s` дотор `(tx_index, ix_index) > trigger` байх арилжаа ч.

Минуенд нь peer-д хамаарахгүй (`slot ≤ s+τ` бүх мөрийн нийлбэр), хасагдагч нь `ROWS` frame тул мөрөөр яг тасарна |

### ⚠ Траектор ба мөрийн хилийн зөрчил (шалгасан, зассангүй)

Траектор нь slot тутмын `slot_flow` нийлбэр дээр баригддаг тул **мөрийн хилийг илэрхийлэх чадваргүй**. `incl_pre` дор `a = 1, 2` үед цонх `(s+a−3, s+a]` нь slot `s`-ийг **бүхэлд нь** агуулна — trigger-ээс өмнөх ба хойшхи арилжаа хоёуланг. Өөрөөр хэлбэл траекторын эхний хоёр элемент нь жинхэнэ **өнгөрсөнийг** ирээдүйн цонхонд хольж байна.

Хэмжсэн: кэшлэгдсэн 88 burst-ийн **52 (59.1%)** нь өөрийнхөө slot дотор өмнө болсон арилжаатай — өөрөөр хэлбэл тохиолдлын талаас илүүд нь энэ холилт идэвхтэй.

Засах бол траекторыг slot биш **мөрийн** түвшинд дахин барих шаардлагатай (`slot_flow`-ийн оронд prefix-difference), энэ нь §4.3-ийн семантикийн өөрчлөлт тул **шийдвэр**. Зассангүй, тоог тайлагнав.
