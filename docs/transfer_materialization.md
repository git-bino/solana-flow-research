## 1. Python лавлагааны засвар (0 credit)

`decisions.md`-ийн шийдвэрээр **сөрөг `held` дээрх buy нь шинэ позиц эхлүүлнэ** — SQL-ийн
зан төлөв эрх мэдэлтэй. `src/oh_reference.py`-д:

- `held ≤ 0`-ийн шалгалт sell салаанаас гарч, **event тутмын нийтлэг дүрэм** болов
  (`_mark_if_flat`) — buy, sell, transfer-out, transfer-in дөрвүүлээнд адил.
- Reset нь **хойшлогдсон**: `held ≤ 0` болсон мөр өөрөө хуучин basis-аа хадгалж,
  **дараагийн мөр** шинэ segment эхлүүлнэ (`_roll_segment`). Энэ нь SQL-ийн
  `ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING`-ийн семантик.
- Хуучин зан төлөв `legacy_negative_held` тугаар үлдсэн.

## 3–4. Materialization ба лавлах туршилт — **ЗОГССОН, асуулт гарсан**

Query бичигдсэн (`sql/materialize_transfers.sql`), 9 хоногийн зүсмээр параметржүүлсэн.
Гэвч **гаралтыг Dune дээр хадгалж дахин лавлах цорын ганц хэмжигдсэн зам нь query-г
НИЙТИЙН болгох** шаардлагатай:

| хэмжсэн зүйл | үр дүн |
|---|---|
| `SELECT * FROM query_8378270` | `Cannot query Query 8378270: querying **private** queries is an advanced feature` |
| Тэр query-ийн төлөв | `is_private: True`, эзэмшигч `quantbino1695` |
| Analyst plan дээр хувийн query лавлагдах эсэх | **ҮГҮЙ** — дээрх алдаа Analyst түлхүүрээр гарсан |
| `dune` schema | Dune-ийн өөрийн cross-chain хүснэгтүүд, хэрэглэгчийн үр дүнгийн орон зай биш |

Query-г нийтийн болгох нь **гадагш чиглэсэн нийтлэл** — universe-ийн дүрэм, хасалтын
дүрэм, mint-ийн олонлог зэрэг судалгааны аргачлалыг ил болгоно. Энэ нь миний
шийдэх зүйл биш тул **ЗОГСООД асуув**.

Зардлын тооцоо хэвээр: 9 хоногийн зүсэм тутам ~5.6 cr (нэг өдрийн хэмжсэн 1.259-аас
scan давамгайлах тул шугаман бус), 8 зүсэм ≈ **45 cr**; гаралт **0.071 GB**.
