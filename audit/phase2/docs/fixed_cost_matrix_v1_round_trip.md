## 0. Юу нэмэгдсэн

`src/cost_model.py`-ийн `net_pnl`-д **`fixed_cost_per_trade`** параметр нэмэгдэв
(анхдагч `0`, тиймээс өмнөх бүх үр дүн **өөрчлөгдөөгүй** — `pytest -q` 297 passed).

```
net P&L = (x₂ − x_f)·(1 − f) − q/(1 − f) − 2·pf − fixed_cost_per_trade
```

Бүрдэл: ATA rent ~0.002 SOL (буцаагдах боловч эхэлж төлнө), base signature fee
0.000005 × 2 транзакц, priority fee / Jito tip 0 … 0.001.

> **⚠ ТОДОРХОЙГҮЙ ЗҮЙЛ, ил тэмдэглэв — өөрөө шийдээгүй.** `fixed_cost_per_trade` гэдгийг
> **нэг эргэлтэд** (орох + гарах) гэж хэрэгжүүлэв: даалгаврын тор {0, 0.0005, 0.001, 0.002,
> 0.005} ба бүрдэл нь (ATA rent нэг удаа, signature fee «× 2 транзакц») эргэлтийн **нийт** дүн
> шиг унших боломжтой. Хэрэв **хөл тутам** гэсэн утгатай бол доорх бүх `fixed / q` тоо **хоёр
> дахин** болно. Аль уншлага зөв вэ?

Тогтмол зардал нь `q`-тэй масштаблагддаггүй тул **өгөөжид `fixed / q`** гэж ордог.

## 2. ГОЛ АСУУЛТЫН ХАРИУ

**«`q = 0.05` дээр `fixed = 0.001` нь 2% — ирмэг үхэх үү»**

| | |
|---|---|
| `fixed / q` тэр нүдэнд | **2.00%** |
| хамгийн сул нүдний E[ret] | **+27.09%** → **+25.09%** |
| хамгийн хүчтэй нүдний E[ret] | **+53.92%** → **+51.92%** |

**Торын 25 нүдийн 25 нь эерэг үлдэнэ** (хамгийн сул нүд дээр ч). Хамгийн хатуу нүд
(`q = 0.05`, `fixed = 0.005`) нь **10.00%** зардал бөгөөд хамгийн сул E[ret]-ийг
**+27.09% → +17.09%** болгоно.

**Тэмдгээ солих хил:** `q = 0.05` дээр хамгийн сул нүд **`fixed < 0.0135 SOL`** хүртэл эерэг —
даалгаврын хамгийн өндөр торын утга (0.005) -аас **2.7 дахин** дээгүүр.

> **Гэхдээ:** энэ нь **дундажийн** тухай мэдэгдэл. `trim5` нь тогтмол зардалгүйгээр ч бүх
> нүдэнд **сөрөг** (−6.90% … −12.19%), median мөн сөрөг. Тогтмол зардал нь **арилжаа бүрд**
> ногддог тул аль хэдийн алдагдалтай байгаа 95%-ийг улам гүнзгийрүүлнэ; дундажийн тэмдгийг
> өөрчлөхгүй, учир нь дундаж нь дээд децилээс гарч байна.

## 3. Хязгаарлалт — юуг тааварлаагүй

**`q ≠ 1` дээрх пропорциональ хэсэг нь `q = 1`-ийн утгаараа тогтоогдсон.**
Дээрх матрицын **зөвхөн `fixed / q` гишүүн** нь `q`-гээр өөрчлөгдөж байна;
`E[ret_prop](q)` нь хэмжигдээгүй тул `E[ret_prop](1)` дээр бэхлэгдсэн.
**ЭНЭ БОЛ CLAUDE CODE-ИЙН ШИЙДВЭР** (танилцуулгын хэлбэр; тоог өөрчлөөгүй, бэхлэлтийг ил бичив).

Бэхлэлтийн алдааны **хэмжсэн** хэмжээ — `docs/h3_economics.md`-ийн q-зурвасаас (ижил H3
популяци, өөр хаалтын тохиргоо):

| хос | q = 0.5 | q = 1 | q = 2 | Δ нэгж `q` тутам |
|---|---|---|---|---|
| `cre t1`, +36/−30 | +2.00% | +1.70% | +1.20% | **≈ −0.40 пункт** |
| `cre t1`, +20/−20 | +0.27% | +0.12% | −0.12% | ≈ −0.25 пункт |
| `gini t1`, +20/−20 | −2.78% | −2.86% | −3.01% | ≈ −0.15 пункт |

→ `q ≤ 2` дээр бэхлэлтийн алдаа **≤ 0.5 пункт**; `q = 5` дээр **≈ 0.6 … 2.0 пункт**
(эерэг талдаа хазайлттай, учир нь бага `q` дээр slippage бага). `fixed / q` гишүүн нь
0 … 10.00% мужид хөдөлдөг тул `q ≤ 2` дээр бэхлэлт нь **хоёрдогч**; `q = 5` дээр харин
slippage-ийн гишүүн `fixed`-ийнхээс **том**.

> **АСУУЛТ УДИРДАГЧИД:** `q ∈ {0.05, 0.1, 0.5, 5}` дээрх пропорциональ хэсгийг **яг**
> тооцохын тулд `sql/execution_gap_agg.sql`-ийг тэдгээр `q`-тай дахин ажиллуулах хэрэгтэй.
> **Зардлын тооцоо ~0.2 credit** (өмнөх ажиллуулалт 0.181, зөвхөн багана нэмэгдэнэ), × 3 = 0.6.
> Ажиллуулах уу?

### ⚠ Хажуугаар илэрсэн миний согог — `docs/h3_economics.md`-ийн «шимтгэл хассан» багана

`sql/h3_economics.sql` нь шимтгэл-зөвхөн өгөөжийг **`r²(1−f)² − 1`** гэж бичсэн.
Зөв нь **`r²(1−f) − 1/(1−f)`** — шимтгэл нь орлогоос **хасагдаж**, зарлагад **нэмэгддэг**,
энэ нь нэг үржүүлэгчийг квадрат болгохтой ижил **биш**. (Энэ нь `tests/test_anchor_rule.py`-ийн
`test_price_is_proportional_to_x_squared_in_the_small_q_limit`-ийг бичихэд илэрсэн; миний
анхны хүлээлт мөн буруу байсан, код зөв байсан.)

Зөрүү = `f/(1−f) − r²(1−f)f`. `r ≈ 1` дээр **+0.03 пункт**; `E[r²] = 1.86` (`+135%`-ийн
`зорилтгүй` мөр) дээр **−1.05 пункт**.

**Гол тоонууд өртөөгүй:** `q = 0.5/1/2` баганууд нь `cost_model`-ийн яг замыг ашигласан;
зөвхөн «шимтгэл хассан» лавлагааны багана л энэ зөрүүтэй. Дахин ажиллуулах нь ~0.05 credit;
**ажиллуулаагүй**, `docs/h3_economics.md`-д залруулга шаардлагатай.
