## C. Power analysis

### Аргачлал

**Bootstrap: pigeonhole two-way (Owen 2007), 8 assignment × 250 давталт = 2,000.**

- Токены кластерыг **орлуулалттай** дахин түүвэрлэнэ, минутын кластерыг мөн адил;
  мөр бүрийн жин = хоёр олонлогийн үржвэр. Энэ бол **crossed** (үүрлэсэн биш) хоёр
  талт кластерт зориулагдсан схем — токен ба минут нь хоорондоо үүрлэдэггүй.
- **Энгийн i.i.d. bootstrap ашиглаагүй** (урьдчилж хориглосон): burst нь токен дотор
  давтагдаж, минут дотор овоордог тул мөрийг бие даасан гэж үзэх нь буруу.
- H0 нь "эрэмбэлэгч хувьсагч мэдээлэл агуулахгүй" тул decile-ийн харьяаллыг
  **санамсаргүйгээр** оноож, outcome-д огт хүрэхгүй. Оноолт нь design тутам **нэг удаа**
  сугалагдаж, кластер дахин түүвэрлэгдэх зуур тогтмол байна — энэ нь бодит estimator-ыг
  давтана (decile нь `OH_ratio`-оор тогтмол, дуу чимээ нь датанаас).
- Статистик: `median(d10) − median(d1)`, жинтэй median-ээр.
- `MDE = (z₀.₉₇₅ + z₀.₈₀) × SE = 2.8016 × SE`.

**Оноолтын хоёр схем — үр дүнг хаалтад оруулах зорилготой (ЭНЭ БОЛ CLAUDE CODE-ИЙН
ШИЙДВЭР).** Бодит decile нь `OH_ratio`-оор тогтоогдох ба `OH_ratio` нь токен дотор хэр
тогтвортойг мэдэх нь SE-д ихээхэн нөлөөтэй. Гэвч энэ алхамд `OH_ratio`-той ямар ч ажил
хориотой тул түүнийг **хэмжихгүйгээр** хоёр захын тохиолдлыг гаргав:

| схем | утга |
|---|---|
| **row-level** | decile нь мөр тутам санамгүй — `OH_ratio` токен дотор огт тогтворгүй бол |
| **token-level** | токен бүхэлдээ нэг decile-д — `OH_ratio` токен дотор бүрэн тогтвортой бол |

Бодит хариу энэ хоёрын хооронд байна.

### Үр дүн

Хоёр схем бараг ижил гарсан (зөрүү 2.3%) — өөрөөр хэлбэл **энэ өгөгдөл дээр decile-ийн
оноолт токен түвшинд байх эсэх нь SE-д бараг нөлөөгүй**. Шалтгаан нь B-д харагдана:
токены median burst нь 1, тиймээс "токен бүхэлдээ нэг decile-д" гэдэг нь ихэнх токенд
"мөр бүхэлдээ нэг decile-д"-тэй ижил утгатай.

**Design effect:** аналитик i.i.d. лавлагаа SE = 0.025244 SOL (зөвхөн харьцуулалтад,
инференцэд ашиглаагүй) → хоёр талт кластер нь дисперсийг **3.0 дахин** (SE-г 1.74 дахин)
өсгөж байна. Кластерын залруулга бодит ажил хийж байна.

### Эдийн засгийн босго (§7 kill criterion (ii))

Лавлагаа нөхцөл: `x = 50`, `q = 1 SOL`, **L2 latency**, `fees = 0.025`.
§5-д L2 = 1000ms, slot нь 400ms → **2.5 slot**.

`V` (latency-ийн үеийн урсгал) нь датанаас. Extract нь 2.5 slot-ийг **тойрсон** бүхэл
slot цонхтой (`v_latency_2slot` = s+1..s+2, `v_latency_3slot` = s+1..s+3), тиймээс мөр
тутам **шугаман интерполяци** хийж, дараа нь median авав (ЭНЭ БОЛ CLAUDE CODE-ИЙН
ШИЙДВЭР; хоёр захыг мөн гаргасан тул интерполяцийн жин ил байна):

| | SOL |
|---|---|
| median `v_latency_2slot` | **0.000000** |
| median `v_latency_3slot` | **0.000000** |
| **V (2.5 slot, интерполяци) median** | **0.000000** |
| V p75 | 0.409886 |
| V p90 | 2.070035 |
| V p99 | 9.304122 |
| V яг тэг байх хувь | **26.39%** |

**Median burst-ийн latency-ийн үеийн урсгал тэг** — median burst-ийн дараа 2.5 slot-ийн
дотор ямар ч арилжаа land хийхгүй. Мөрүүдийн 26.4% нь яг тэг. Энэ нь өмнөх
диагностикийн `death_age` median 3.0 slot-той нийцэж байна. **Интерполяци нь энэ тохиолдолд
хамааралгүй** — хоёр зах хоёулаа 0.

```
BE = (1 + V/x)² · (1 + q/x)² · (1 + fees) − 1
   = (1 + 0/50)² · (1 + 1/50)² · 1.025 − 1
   = 1.0404 · 1.025 − 1
   = 0.066410
```

§7 (ii) нь тестийг шууд бичсэн: decile 10-ийн median `fwd_net_flow(12slot)`-ээс гарах
үнийн хөдөлгөөн `(1 + ΔV/x)² − 1` нь BE-ээс их байх ёстой. Урвуулбал (ЭНЭ БОЛ CLAUDE
CODE-ИЙН ШИЙДВЭР — §7-ийн томьёоны шууд урвуу):

```
ΔV_шаардлагатай = x · (√(1 + BE) − 1) = 50 · (√1.066410 − 1) = 1.633565 SOL
```

| | row-level | token-level |
|---|---|---|
| MDE | 0.125779 SOL | 0.122938 SOL |
| ΔV шаардлагатай | 1.633565 SOL | 1.633565 SOL |
| MDE / босго | **7.7%** | **7.5%** |
| Босгын хэмжээний эффект дээрх power | **≈ 100.00%** | **≈ 100.00%** |
| **power ≥ 80%?** | **ТИЙМ** | **ТИЙМ** |

**Power ≥ 80% — ТИЙМ, хоёр схемийн аль алинд нь, ихээхэн нөөцтэйгээр.**

Одоогийн дээж нь эдийн засгийн босгоос **13 дахин жижиг** эффектийг 80%-ийн power-тэй
барих чадвартай (0.123 vs 1.634 SOL). Босгын хэмжээний d10−d1 зөрүү байгаа бол
энэ дата түүнийг бараг тодорхойгүйгээр илрүүлнэ.

**§7-ийн үл хамаарах заалт ИДЭВХЖИХГҮЙ.** Power < 80% биш тул 3b дээр CI тэгийг
агуулбал тэр нь "дата хүрэлцэхгүй" биш **"сигнал байхгүй"** гэж уншигдана — өөрөөр
хэлбэл kill criterion (i) бүрэн хүчинтэй ажиллана.

Дээж нэмэх шаардлагагүй тул үржүүлэгч тооцоогүй (шаардлага үүсээгүй). Лавлагаанд:
80%-ийн power-ыг босгын хэмжээнд хадгалахад одоогийн кластерын тооны **0.6%** нь л
хангалттай байх байсан (`(0.1229/1.6336)² = 0.0057`).

### Тайлбарлахад анхаарах зүйл

Энэ бол **зөвхөн power-ийн мэдэгдэл** — эффект БАЙГАА гэсэн ямар ч заалт биш.
`OH_ratio`-той холбоотой юу ч энд хэмжигдээгүй. d10−d1 зөрүү бодитоор хэд болох нь
**3b-ийн асуулт**.

## Гаргасан шийдвэрүүд (ЭНЭ БОЛ CLAUDE CODE-ИЙН ШИЙДВЭР)

1. **Double-cluster схем = pigeonhole two-way bootstrap** (Owen 2007). Токен ба минут нь
   crossed кластер бөгөөд үүрлэдэггүй тул нэг талт block bootstrap хангалтгүй.
2. **Decile оноолтын хоёр схем** (row-level ба token-level) — `OH_ratio`-ийн токен доторх
   тогтвортой байдлыг хэмжих нь энэ алхамд хориотой тул хоёр захыг гаргаж хаалтад оруулав.
3. **V-г 2.5 slot дээр шугаман интерполяциар** (`v_latency_2slot` ба `_3slot` хооронд),
   мөр тутам, дараа нь median. Хоёр зах хоёулаа 0 тул үр дүнд нөлөөгүй.
4. **ΔV_шаардлагатай = x·(√(1+BE) − 1)** — §7 (ii)-ийн `(1+ΔV/x)² − 1 ≥ BE` нөхцөлийн
   шууд урвуу.
5. **B = 2,000 давталт** (8 × 250), seed 20260819. SE-ийн SE ≈ 1.6%.
6. **Минутын кластерыг `block_time`-аас** (burst-ийн бодит цаг) гаргав; `minute_bucket`
   баганатай зөрүү 0 болохыг шалгасан.
