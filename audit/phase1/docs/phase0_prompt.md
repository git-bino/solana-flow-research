## Гүйцэтгэх дараалал

### 0.1 Дата хэмжээний тооцоо (ЭХЛЭЭД, татахаас өмнө)

90 хоногийн бүрэн universe-ийн токен ба event тоог **тооцоолж** гарга (бүрэн татахгүйгээр — жишээ нь 3 хоногийн дээж дээр). Дараа нь:
- Dune credit-ийн шаардлага
- Локал ClickHouse-ийн дискний шаардлага

Хэрэв багтахгүй бол §2.2-ийн **санамсаргүй токен түүврийн** дүрмээр л багасга: mint hash-аар тогтмол хувь. Идэвх, эзлэхүүн, наслалт, migration-аар шүүхийг **хатуу хориглоно**. Түүврийн хувийг `decisions.md`-д бичиж commit хий — дараа өөрчлөхгүй.

### 0.2 Universe тодорхойлолт

`[T_start, T_end]` хооронд **үүсгэгдсэн** бүх pump.fun токен. Migration бол label, шүүлт биш. Migrate хийгээгүй, бүр 5 арилжаатай үхсэн токенууд ч дотор байх ёстой.

Хугацааны сүүлийн 30%-ийг **тусад нь `data/holdout/` руу** бичээд, үндсэн pipeline-ээс бүрэн гарга. Holdout-ыг уншдаг ямар ч код Phase 7 хүртэл бичигдэхгүй.

### 0.3 Fee handling (v1.1-ийн шинэ шалгалт — ЧУХАЛ)

Dune-ий decoded `sol_amount` нь **gross (шимтгэл орсон) эсвэл net** үү — тодорхойл, баримтжуул.

Энэ нь буруу бол curve reconstruction системтэйгээр ~1% зөрөх бөгөөд доорх 0.01 SOL-ын шалгалтыг **жинхэнэ алдаагүйгээр** унагана. Тиймээс:
1. Аль болохыг эхлээд тогтоо (on-chain instruction data эсвэл хэдэн арилжааг гараар шалгаж)
2. Сонгосон тодорхойлолтоо `results/phase0_report.md`-д бич
3. `curve.py`-ийн x reconstruction тэр тодорхойлолттой нийцэж байгааг тусад нь батал

### 0.4 Curve reconstruction

`x_pre`, `x_post`-ыг §1.1-ийн `x·y = k`, `x₀ = 30`, `y₀ = 1,073,000,191`-ээр сэргээ.

Мөнгөн дүнгийн floating point алдаа хуримтлагдаж байвал `Decimal` ашигла — 10⁵ event дараалсны дараа зөрүү мэдэгдэхүйц болох эсэхийг тусад нь шалга.

## Kill criterion (PASS/FAIL тодорхой гарга)

| # | Шалгалт | Босго |
|---|---|---|
| 1 | Reconstructed `x_post` vs on-chain state | зөрүү < 0.01 SOL, event-ийн **>99%** дээр |
| 2 | Curve-ээр бодсон үнэ vs бодит `sol_amount/token_amount` | таарах ёстой |
| 3 | Universe launch-аар тодорхойлогдсон | migrate хийгээгүй токенууд дата дотор **байгаа** |
| 4 | Өдрийн event тоо тогтвортой | огцом уналт = дата дутуу |
| 5 | `x_post` ба дараагийн `x_pre`-ийн залгаа | токен бүр дотор тасралтгүй |
| 6 | Fee handling тодорхойлогдсон | §0.3-ийн 3 алхам гүйцэтгэгдсэн |

> **KILL:** Шалгалт 1 давахгүй бол цааш явахгүй. Бүх зүйл curve reconstruction дээр тогтоно. FAIL гарвал зогсоо, шалтгааныг тайлагна, дараагийн phase руу бүү үргэлжлүүл.

## Ерөнхий дүрмүүд (spec §6, §8.2)

1. Бүх feature backward-looking. t мөчид `block_time > t` өгөгдөл ашиглах нь bug — Phase 0-д feature байхгүй ч, `curve.py`-ийн интерфейс энэ дүрмийг зөрчих боломжгүй байхаар зохион байгуул.
2. Slot доторх дараалал `tx_index`-ээр. `ORDER BY (token_mint, slot, tx_index)`.
3. Тайлагналд median + 10% trimmed mean + bootstrap 95% CI — дан mean битгий.
4. Kill criterion-ий үр дүнг **PASS эсвэл FAIL** гэж тодорхой бич.
5. Дата руу харсан шалгалт бүрийг `test_log.md`-д бүртгэ (огноо, phase, юу шалгасан, үр дүн).
6. Ажиллуулахын өмнө энэ prompt болон kill criterion-ыг commit хий.
