| Шалгалт | Үр дүн |

| `bursts_kept` монотон, mayhem | 2,974 ≤ 3,003 ≤ 3,008 ≤ 3,009 ≤ 3,019 → **PASS** |

| `events_kept` монотон, mayhem | 1,342,396 … 1,439,546 → **PASS** |

| Slot-суурьтай нийт burst vs 2s-ойролцоолол 42,094 | **39,088 → −7.14%** (босго 40%, тэмдэглэх шаардлагагүй) |
| Event-ийн нийт тоо vs өмнөх хэмжилт 6,625,821 | 6,632,789 → **+0.105%** |

**−7.14% ба +0.105%-ийн шалтгаанууд** (нэгж/хил өөрчлөгдсөнөөс, алдаа биш):

1. Цонх `2s` → `5 slot` (≈2.0s) болсон, мөн `10s` → `25 slot` (≈10.0s).
2. Дараалал: өмнө `block_time`-аар (1 секундын мөшгилт), одоо `(slot, tx_index, ix_index)`-аар. Нэг слот доторх дараалал одоо тодорхой.
3. `x(t)`: өмнө арилжааны **өмнөх** x (`vsol − ±sol`), одоо мөрийн `virtual_sol_reserves` **шууд** (арилжааны дараах) — prompt-ийн заалт. Босго `0.10 × x` тул post-trade x нь buy дээр бага зэрэг өндөр босго өгнө.
4. Event-ийн хил: өмнө `evt_block_date < 2026-06-11`, одоо `<= 2026-06-11` ба `block_time < 23:59` → +6,968 event (+0.105%).
5. Intra-slot lookahead арилсан: `net_flow_5slot` нь одоо prefix sum-ийн зөрүүгээр бодогдож, тухайн мөрөөр таслагддаг. `RANGE 4 PRECEDING … CURRENT ROW` бол нэг слот дотор дараа гүйцэтгэгдэх мөрүүдийг чимээгүй оруулах байсан (spec §6.1).
